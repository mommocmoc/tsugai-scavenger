# Scavenger

[English](README.md)

2인치 화면 속에서 살아가는 츠가이(つがい, 한 쌍).

화면은 칠흑처럼 어둡습니다. 작은 초록빛 하나가 물 위의 종이 등불처럼 숨을 쉬듯 밝아졌다 어두워지며 떠돕니다. 건드리지 않는다면 그게 전부입니다.

화면을 터치하면 어둠 속에서 愛(아이)가 솟아오릅니다. 머리 위에 그 램프를 매단 채 무엇이든 삼켜버리는 입을 벌린 심해 아귀입니다. 물 위에 떠돌던 무언가를 덥석 집어삼킵니다. 삼켜진 덩어리가 몸속을 타고 천천히 내려갑니다. 전율하듯 몸을 한번 떨고 나면 삼켰던 것을 다시 토해내고 — 그 앞에는 작고 창백한 誠(마코토)가 이미 건네받을 채비를 마친 채 기다리고 있습니다.

`HERE. TAKE IT.`

이윽고 아귀는 다시 깊은 곳으로 가라앉습니다. 마지막 순간까지 빛나던 램프마저 서서히 사그라들면, 화면은 다시 적막한 어둠으로 돌아갑니다.

掃除屋(소지야) — 어지러운 것을 삼켜 치워주는 청소부.

## 준비물

| 구분 | 사양 |
|---|---|
| 보드 | Waveshare ESP32-S3-Touch-LCD-2 (2.0인치 ST7789 IPS, 320×240, CST816 터치) |
| 케이블 | USB-C **데이터** 케이블 (충전 전용 케이블은 겉모습이 같지만 통신이 되지 않습니다) |
| 호스트 환경 | macOS 또는 Linux, 색상 변환 도구용 Python 3 |

microSD 카드도, 외장 센서도, 네트워크 연결도 필요 없습니다. 화면 위의 모든 것은 순수 코드로 그려집니다.

터치 패널이 없거나 동작하지 않는 보드여도 괜찮습니다. `TOUCH_ENABLED`를 `false`로 설정하면 몇 초 간격으로 스스로 헤엄쳐 올라옵니다.

## 실행하기

```bash
./tools/setup.sh     # arduino-cli, ESP32 코어, 그래픽 라이브러리 설치
./tools/build.sh     # 컴파일 (보드 연결 없이도 가능)
./tools/flash.sh     # 보드를 연결하고 펌웨어 업로드
```

`setup.sh`는 멱등(idempotent)하게 동작하므로 여러 번 실행해도 안전합니다(이미 완료된 항목은 건너뜁니다). 보드가 인식되지 않는다면 `./tools/doctor.sh`를 실행해 보세요. 요구사항을 하나씩 점검해 빠진 부분을 친절하게 짚어줍니다.

## 설정 변경

조절할 수 있는 모든 설정값은 **`scavenger/config.h`** 파일 하나에 모여 있으며, 각 줄마다 상세한 주석이 달려 있습니다. 다른 파일은 건드릴 필요가 없습니다.

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| `SPIT_LABEL` | `"BFG-9000"` | 스캐빈저가 토해내는 물건의 이름. 마지막 프레임에 출력 (~24자 이내) |
| `FRAME_MS` | `10` | 프레임 간 대기 시간(ms). 작을수록 애니메이션이 빨라집니다 |
| `TOUCH_ENABLED` | `true` | 터치로 불러내기. `false`면 주기적으로 자동 재생됩니다 |
| `AUTO_PLAY_MS` | `6000` | 터치가 없을 때, 램프가 유영하다 스스로 올라오는 주기(ms) |
| `LAMP_DRIFT_X` / `_Y` | `40` / `22` | 램프의 이동 반경 (캔버스 픽셀 단위, 캔버스 크기: 160×120) |
| `LAMP_GLOW` | `9` | 램프의 기본 밝기 (1–10) |
| `LAMP_BREATH` | `3` | 숨쉬듯 빛이 일렁이는 밝기 변화폭 |
| `SCREEN_BRIGHTNESS` | `85` | 화면 백라이트 밝기 (0–100) |
| `SCREEN_ROTATION` | `1` | 화면 회전 (`1`: 기본 가로 모드, `3`: 180° 반전) |

해당 파일의 섹션 4는 보드 핀 맵입니다. 하드웨어 보드를 바꾼 게 아니라면 수정하지 말고 그대로 두세요.

## 내부 구조

모든 그래픽은 160×120 크기의 캔버스에 그린 후 디스플레이 패널에 2배 크기로 정수 배율 확대하여 출력합니다. 픽셀이 다소 거칠게 보이는 것은 의도된 연출입니다 — 안티앨리어싱도, 매끄러운 곡선 처리도 없으며, 팔레트는 `scavenger.h` 상단에 손수 고른 20가지 RGB565 색상이 전부입니다.

| 소스 파일 | 담당 역할 |
|---|---|
| `scavenger/scavenger.ino` | 부팅 처리, 대기 중 램프 유영, 연극의 막을 올리는 진입점 |
| `scavenger/scavenger.h` | 컬러 팔레트, 愛와 誠 및 램프 렌더링, `scavPlay()` 연출 시퀀스 |
| `scavenger/config.h` | 변경 가능한 모든 설정값 모음 |
| `scavenger/lowres.h` | 캔버스 버퍼 관리, 2배 blit 확대, 프레임 타이밍 제어, 보조 유틸리티 |
| `scavenger/touch.h` | CST816 터치 컨트롤러 — 터치 발생 및 좌표 감지 |

`scavPlay()`는 총 9개의 씬(scene)으로 구성됩니다: 홀로 떠도는 등불 · 어둠을 뚫고 서서히 드러나는 아귀의 형체 · 쩍 벌어지는 턱 · 소멸(단 한 장의 흰색 프레임) · 목구멍을 타고 내려가는 덩어리 · 誠의 등장 · 물건의 인계 · 심해로의 침잠 · 그리고 돌아온 물건과의 마지막 여운. 연출이 시작되면 끝날 때까지 화면 제어권을 독점하는 블로킹(blocking) 함수입니다.

생물의 외형을 바꾸려면 `scavFish()`나 `scavMakoto()`를, 장면을 추가하거나 순서를 바꾸려면 `scavPlay()`를 수정합니다. 새로운 색상을 추가할 때는 16진수 hex 코드를 임의로 적지 말고 다음 변환 도구를 사용하세요:

```bash
python3 tools/rgb565.py "#7fae5e"
```

RGB565는 일반적인 RGB888과 색상 체계가 다릅니다. 상수를 잘못 입력하면 컴파일 에러가 나는 대신 전혀 의도치 않은 엉뚱한 색상으로 출력됩니다.

`config.h` 외의 소스 코드를 수정했다면 다음 검증 스크립트를 실행해 보세요:

```bash
./tools/verify.sh    # 동작 조건이 다른 모든 설정 조합을 빌드 검증
```

## 문제 해결

| 증상 | 점검 방법 |
|---|---|
| 화면에 아무것도 나오지 않음 | `./tools/monitor.sh`를 실행한 상태에서 보드의 **RESET** 버튼을 누르세요. 부팅 로그에 LCD 초기화 성공 여부가 표시됩니다. |
| 업로드 실패 또는 시리얼 포트 미인식 | 보드의 **BOOT** 버튼을 누른 채 **RESET** 버튼을 딸깍 누르고, **BOOT** 버튼을 뗀 후 `flash.sh`를 다시 실행해 보세요. |
| 화면을 터치해도 반응이 없음 | 부팅 로그에서 CST816 터치 패널의 응답 여부를 확인하세요. 터치를 지원하지 않는 패널이라면 `TOUCH_ENABLED false`로 설정합니다. |
| 텍스트가 화면 밖으로 잘림 | 160px 캔버스에서 6px 고정폭 폰트를 사용하므로, 약 26자를 초과하면 경고 없이 잘려 나옵니다. |
| 색상이 이상하게 보임 | 의도한 16진수 색상 코드를 `tools/rgb565.py`로 변환한 값과 `scavenger.h`에 정의된 값을 비교해 보세요. |

`./tools/doctor.sh`를 한 번 실행해 보면 대부분의 문제 원인을 즉시 파악할 수 있으며, 그 출력 결과는 AI 코딩 에이전트에 그대로 전달해 진단을 받기 좋게 구성되어 있습니다.
